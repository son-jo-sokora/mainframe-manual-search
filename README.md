# mainframe-manual-search

IBM のメインフレーム製品（IBM z/OS、IBM Db2 for z/OS、IBM IMS、IBM CICS Transaction Server、IBM MQ など）のマニュアル PDF を、
**自分の PC の中だけで**すばやく検索できるようにするツールです。
個人が作った非公式のツールで、IBM とは関係がありません（下の「ライセンスと商標」）。

- `IEF450I` のようなメッセージ ID や `S0C4` のようなアベンドコードを入れると、その**説明が載っているページ**を最初に出します。
- 「データセットが見つからないときのエラー」のように**日本語の文章で聞いても**、英語のマニュアルの関係するページを探します。
- ジョブのログを貼り付けると、出てくるメッセージやコードを全部拾って、それぞれの説明のページを並べます。
- 同じマニュアルの古い版と新しい版を比べて、何が変わったかを一覧にします（バージョンアップの調査に使えます）。

検索はすべて手元で動きます。マニュアルの中身をインターネットに送ることはありません。

> **このリポジトリにマニュアルは入っていません。** PDF は各自が IBM のサイトからダウンロードしてください
> （下の「ライセンスと商標」も読んでください）。

## しくみ（ざっくり）

```
マニュアルの PDF ─①─▶ テキスト ─②─▶ 全文検索の索引 ─③─▶ 意味検索の索引 ─▶ ブラウザで検索
```

1. PDF から文字を取り出してテキストにします。
2. 単語で引くための索引（SQLite）を作ります。メッセージ ID などはここで引きます。
3. 文章の意味で引くための索引を作ります。日本語の問いで英語の本文を探せるのはこの部分のおかげです。
   AI の「埋め込みモデル」を使うので、NVIDIA の GPU があると速く終わります。

①〜③は最初に一度やれば、あとは検索するだけです。マニュアルを追加したときだけ、もう一度やります。

## 用意するもの

| もの | 何に使うか | 無いとどうなるか |
|---|---|---|
| Python 3.9 以上 | このツールを動かす | 動きません |
| poppler（`pdftotext` コマンド） | PDF から文字を取り出す | 動きません |
| NVIDIA の GPU と、CUDA 版の PyTorch | 意味検索の索引を作る・使う | CPU でも動きますが、索引づくりがとても遅くなります |
| ripgrep（`rg` コマンド） | 単純な文字列検索を速くする | 無くても動きます |
| ディスクの空き | PDF・テキスト・索引の置き場所 | 目安は下の表 |

ディスクの目安（実例：マニュアル約1000冊の場合）：

| もの | 大きさ |
|---|---|
| PDF | 約3〜10GB（集める製品による） |
| 取り出したテキスト | 約1GB |
| 全文検索の索引 `index.db` | 約1.8GB |
| 意味検索の索引 `vectors.f16` | 約2GB |

### インストールのしかた

poppler と ripgrep：

| OS | poppler | ripgrep |
|---|---|---|
| Windows | `conda install -c conda-forge poppler` など。`pdftotext` が PATH から実行できれば何でもよい | `winget install BurntSushi.ripgrep.MSVC` |
| Ubuntu / WSL2 | `sudo apt install poppler-utils` | `sudo apt install ripgrep` |
| Mac | `brew install poppler` | `brew install ripgrep` |

Python のライブラリ：

1. 仮想環境を作って有効にします（任意ですが、おすすめです）。
   ```
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   source .venv/bin/activate     # Mac / Linux
   ```
2. PyTorch を入れます。https://pytorch.org の「Get Started」で、自分の OS と CUDA の版を選ぶと、入れるコマンドが表示されます。
3. 残りを入れます。
   ```
   pip install -r requirements.txt
   ```
4. GPU が使えるか確かめます。`True` と出れば使えます。
   ```
   python -c "import torch; print(torch.cuda.is_available())"
   ```

この README では、コマンドを `python` と書いています。Mac・Linux で `python` が無い場合は `python3` と読み替えてください。

## マニュアルを集める

1. 置き場所のフォルダを作ります。この README では次の2つを使います。**どちらもこのリポジトリの外**に作ってください。
   - `~/zos-pdfs` … ダウンロードした PDF を入れるフォルダ
   - `~/zos-corpus` … ツールが作るテキストと索引の置き場所
2. IBM Documentation（https://www.ibm.com/docs）の各製品のページから、PDF をダウンロードします。
   z/OS は、版ごとにマニュアルを全部まとめた PDF のパッケージ（zip）が配られています。展開して `~/zos-pdfs` に入れます。
3. 別の製品（Db2、IMS など）は、フォルダを分けると管理しやすくなります（例：`~/db2-pdfs`）。

製品名と版は、PDF の表紙や本文から自動で判断します。判断の決まりと、外れたときの直し方は `docs/INGEST.md` にあります。

## 索引を作る（最初の一回）

① **テキストを取り出す**

```
python extract.py ~/zos-pdfs ~/zos-corpus
```

別の製品のフォルダも、同じ置き場所に追加します。

```
python extract.py ~/db2-pdfs ~/zos-corpus
```

終わったら `~/zos-corpus/failed.tsv` を開いてください。ここに載った PDF は文字を取り出せなかったもので（画像だけの PDF など）、検索には出てきません。
製品名や版の判断が違っていたら、`~/zos-corpus/overrides.tsv` に正しい値を書いて、①をもう一度実行します。

② **全文検索の索引を作る**

```
python build_index.py ~/zos-corpus
```

③ **意味検索の索引を作る**

```
python embed_index.py ~/zos-corpus
```

いちばん時間がかかる工程です（冊数が多いと数時間）。初回は埋め込みモデル（BAAI/bge-m3、約2GB）を自動でダウンロードします。
途中で止めても、同じコマンドでもう一度実行すると続きから再開します。
GPU のメモリが足りないというエラーが出たら、`--batch 32` のように数を小さくして実行してください。

## 検索する

### ブラウザで使う

```
python hsearch.py ~/zos-corpus serve
```

「http://127.0.0.1:8765 で待ち受け中」と表示されたら、ブラウザでそのアドレスを開きます。表示されるまで30秒ほどかかります。
画面でできること：

- **検索**：メッセージ ID、コード、英語の用語、日本語の文章のどれでも入れられます。製品と版で絞り込めます。
- **ページを読む**：結果をクリックすると、マニュアルのそのページを開きます。
- **ログ解析**：ジョブのログを貼り付けると、メッセージとコードの説明を順に出します。
- **版の比較**：古い版と新しい版を選ぶと、追加・削除・変更されたメッセージの一覧を出します。
- **資料一覧**：取り込んだマニュアルの一覧です。

止めるときは、コマンドを実行した画面で Ctrl+C を押します。

### コマンドで使う

```
python hsearch.py ~/zos-corpus q "IEC161I 040-024"
python hsearch.py ~/zos-corpus q "S0C4" --product z/OS --ver 3.2
python hsearch.py ~/zos-corpus triage joblog.txt
python hsearch.py ~/zos-corpus migrate "z/OS 3.1" "z/OS 3.2"
```

| コマンド | すること |
|---|---|
| `q "<問い>"` | 検索。`--product`（製品名の一部）と `--ver`（版）で絞り込み、`--diff` で他の版との違いも表示 |
| `triage <ログのファイル>` | ログの中のメッセージ・コードを全部拾って、説明のページを出す |
| `migrate "<古い版>" "<新しい版>"` | 2つの版のマニュアルを比べる |
| `diff <文書> <ページ>` | あるページを、同じマニュアルの他の版と比べる |
| `serve` | ブラウザ用の検索画面を起動する |

コマンドで使うと、毎回モデルを読み込むので1回30秒ほどかかります。何度も検索するならブラウザのほうが速く使えます。

文字列をそのまま探したいときは、単純な検索の `zsearch.py` も使えます（意味検索の索引が無くても動きます）。

```
python zsearch.py ~/zos-corpus find "IEF450I" -F
python zsearch.py ~/zos-corpus page text/zos-pdfs/xxx.txt 412
```

## マニュアルを追加・入れ替えたとき

1. **検索の画面（`serve`）を止めます。** 動いたままだと、Windows では索引のファイルを置き換えられません。
2. ①②③をもう一度実行します。①は新しい PDF の分だけ処理します。③も、前と同じ部分は前回の結果を使い回すので、初回よりずっと早く終わります。

## うまくいかないとき

| 症状 | 確かめること |
|---|---|
| `pdftotext` が見つからない | poppler を入れたか、`pdftotext -v` がコマンドの画面で動くか |
| ③で GPU のメモリ不足のエラー | `--batch` の数を小さくする。他に GPU を使うソフトを閉じる |
| ③がとても遅い | `torch.cuda.is_available()` が `True` か。`False` なら CUDA 版の PyTorch を入れ直す |
| 検索結果にマニュアルが出てこない | `failed.tsv` に載っていないか。画面の「資料一覧」に入っているか |
| 製品名や版が違う | `docs/INGEST.md` の手順で `overrides.tsv` に書いて①からやり直す |
| ②③で「ファイルを使用中」のエラー | 検索の画面（`serve`）を止めたか |

## ファイルの説明

| ファイル | 役割 |
|---|---|
| `extract.py` | ① PDF からテキストを取り出し、製品名・版・資料番号を判断する |
| `build_index.py` | ② 全文検索の索引を作る |
| `embed_index.py` / `embedder.py` | ③ 意味検索の索引を作る |
| `hsearch.py` | 検索の本体（ブラウザの画面とコマンド） |
| `triage.py` | ログ解析 |
| `compare.py` / `migrate.py` | 版どうしの比較 |
| `zsearch.py` | 単純な文字列検索 |
| `docs/INGEST.md` | 製品名・版の判断の決まりと、資料を取り込むときの方針 |
